# zhongjing-shuati

中级经济师刷题 skill。一条斜杠命令出题、判卷、自动维护错题本，带间隔重复权重机制。

给 Claude Code / Claude Agent SDK 之类支持 skill 的 agent 用。核心是一个 `pick.py`
和一份写给 agent 看的 `SKILL.md`——**没有服务、没有数据库、没有依赖**，只要有 Python 3.8+。

## 它能干什么

```
你：/shuati 给我出 10 道人力的题
agent：（一次贴出 10 道，只有题干和选项）

你：1B 2ABE 3C
agent：第1题 ✓ ... 第2题 ✗ 正确答案 ABE，你多选了 C，因为...
      （判完自动写进错题本）
```

- **两科分开**：《人力资源管理专业知识和实务》和《经济基础知识》不混编。
- **按考点组织**：题挂在考点上，考点带 ★ 考频星级和近 4 年考察次数，可以只刷 ★★★。
- **模块而非章号**：教材章号年年变，所以按主题模块分层，章号只作次级标签。
- **权重复习**：像背单词软件那样，答对的题逐步少出现，答错的题变常见。
- **错题本是 md**：直接打开就能读，每道错题下面给「完整正确知识点」而不只是本题解析。
- **批量判卷**：题一次全给，你分几批回答都能对上号。

## 权重机制

权重不存表，每次从做题流水现算。连续答对就升级、复习间隔翻倍、权重减半；答错直接
打回第 0 级并立刻到期，而且「错过几次」会长期抬高权重——攻克了也比从没错过的题出现得勤。

间隔序列 `0/1/2/4/8/16/32/64` 天。以全新题为 1.0 基准：

| 情形 | 权重 |
|---|---|
| 全新没做过 | 1.0 |
| 今天刚答对 | 0.03 |
| 昨天答对 1 次 | 0.5 |
| 连对 3 次 | 0.07 |
| 连对 5 次 | 0.01 |
| 今天答错 1 次 | 1.8 |
| 累计错 2 次 | 2.6 |
| 错过 1 次后又连对 3 次 | 0.17 |

抽样用 Efraimidis–Spirakis 带权不放回算法（`key = U^(1/w)` 取前 n），所以低权重的题
只是变少见，不会彻底消失。

## 安装

```bash
git clone https://github.com/<你的用户名>/zhongjing-shuati.git
cd zhongjing-shuati
python3 scripts/pick.py overview       # 应该打印两科的模块和题数
```

Claude Code 里让它变成 `/shuati`：把仓库放进（或软链到）`~/.claude/skills/zhongjing-shuati`，
`SKILL.md` 在仓库根目录，agent 会自己读到。

## 题库数据

**仓库不带题库数据**（`data/` 在 `.gitignore` 里）。`pick.py` 找数据的顺序是：

1. `$SHUATI_BANK` 环境变量
2. 脚本旁边的 `data/`
3. 脚本的上一级目录

所以把你自己的题库放成下面这个样子就能跑：

```
data/
├── 人力资源/
│   ├── 知识点.jsonl        # 考点骨架：★星级、近4年频次、模块、章节
│   ├── 章节.jsonl          # 每章平均分值、学习建议
│   ├── 考点总览.md
│   └── 题目/*.jsonl        # 一行一题
└── 经济基础/
    └── ...
```

题库只读时用 `SHUATI_HOME` 指定错题本写到哪：

```bash
export SHUATI_BANK=/path/to/data
export SHUATI_HOME=~/shuati        # _错题本.md 会写在这里
```

### 题目字段

一行一个 JSON，必填的是 `题目ID` `科目` `题型` `题干` `选项` `答案`：

```json
{
  "题目ID": "HR-Q01689",
  "科目": "人力资源",
  "知识点ID": "HR-KP0013",
  "知识点": "内源性动机",
  "挂靠依据": "文本包含",
  "模块号": 1, "模块": "组织行为",
  "章节号": 1, "章节": "第1章", "所属节": null,
  "题源类型": "母题", "考试年份": "2025", "资料版本": "2025",
  "题型": "多选题",
  "题干": "关于需要、动机的说法，正确的是（　）。",
  "选项": {"A": "...", "B": "...", "C": "...", "D": "...", "E": "..."},
  "答案": "ABE",
  "解析": "本题考查需要。（1）...",
  "卷内题号": 1, "案例组": null, "案例材料": null, "源页码": 2,
  "存疑": null, "质量": "可刷", "重题组": null
}
```

几个字段的作用：

- `质量` — `可刷` 或 `仅参考`。`仅参考` 的题（OCR 残缺、两处收录答案打架）默认不抽。
- `重题组` — 同一道真题在多处收录时给同一个组 ID，取题时自动去重。
- `挂靠依据` — 这题的考点是怎么定的：`位置直接` 最可靠，`本题考查·相似` 最弱，
  讲解时可以据此调整措辞。
- `案例组` — 案例分析题的分组 ID，**必须全局唯一**；同组子题会连着材料一起抽出来不拆开。

## 命令

```bash
P="python3 scripts/pick.py"

$P overview                                   # 题库现状 + 错题本进度
$P pick --科目 人力 --n 10 --藏答案            # 抽题（按权重），只出题面
$P pick --科目 人力 --n 10                     # 抽题，答案解析一起给
$P pick --科目 基础 --星级 3 --n 15            # 只出 ★★★ 高频考点
$P pick --科目 人力 --范围 组织行为 --n 10      # 限定模块/章/题源（模糊匹配）
$P pick --科目 人力 --真题 --n 20              # 只出历年真题
$P pick --科目 基础 --题型 多选题 --n 10
$P pick --科目 人力 --考点 需要层次理论 --n 5
$P pick --科目 人力 --n 10 --均匀              # 关掉权重，纯随机
$P pick --科目 人力 --n 10 --排除已做          # 彻底跳过做过的
$P pick --科目 人力 --n 10 --保留重题          # 不去重

$P answers HR-Q00123:AB EB-Q00353:C           # 按ID取答案+解析，顺手判对错算分
$P answers HR-Q00123 --全选项                  # 只取答案，连选项原文一起打

$P kp 需要层次理论 --科目 人力 --n 3           # 考点讲解 + 关联真题
$P weak --科目 人力                            # 薄弱考点排行
$P wrong --科目 人力 --n 10 --藏答案           # 错题重做（到期的排前面）

$P logs HR-Q00123:错:AB HR-Q00456:对:C         # 批量记结果（判完一批调一次）
$P log --题目ID HR-Q00123 --结果 错 --我的答案 AB
```

科目接受简写：`人力` `hr` `基础` `经基` `eb`。

**判卷必须按题目ID走。** `pick` / `wrong` 的输出开头有一行 `# 题号→ID`，判卷时把 ID
喂给 `answers`。不要拿题干关键词去题库里反查——题干归一化后完全相同、答案却不同的重题
有 166 组（同一考点的单选版/多选版、不同年份的改编版），关键词匹配几乎必然串到隔壁那道。
对错和得分由 `answers` 计算（多选按「错选 0 分、少选每个 0.5 分」的考试规则），
不靠调用方自己比字母。

## 错题本

`log`/`logs` 每次都会整篇重写 `_错题本.md`：

- 按科目 → 考点分组，错得多的考点排前面
- 每题带完整题干选项，✅ 标正确答案，`←我错选了` 标当时踩的坑
- **「要记住的知识点」**：本题解析 + 同一考点其他题的解析归并成完整那张清单
  （单题解析常常只讲被考的那一条，兄弟题的解析往往把整张清单列全了）
- 错过几次、下次复习在几天后；后来做对的挪到「已攻克」

文件末尾 `## 做题流水` 里的 tsv 代码块是程序读的唯一事实来源，别手改。
上半部分是给人看的，会被覆盖。

设计上的一个取舍：**权重不单独存表**，从流水现算。少一个文件，也不会出现权重表和
历史记录对不上的情况。
